# Color1 / Color2 功能分析（待实测确认）

## 现象

样机上单独按 Color1 / Color2，静态模式和动态模式下都看不到任何变化。

## 分析前提（键面与样机的既定事实）

- 遥控器已有 4 个"一键直接变色"键：Red / Green / Blue / White Select，说明"直接选色"这类功能已经被占掉。
- 4 个图标键（国旗 / 三叶草 / 南瓜 / 圣诞树）对应美国市场 4 个节日的配色预设（7月4日红白蓝、圣帕特里克绿、万圣节橙、圣诞红绿），属于"节日配色组合"快捷键。
- 面板上 R6~R9 × C1~C3 共 12 个键位为空，说明这块遥控器面板（按键矩阵）大概率是多个型号共用的通用面板，本 SKU 只用到其中一部分键。
- 样机灯控信号是逐灯数据帧（见 [样机灯光变化规律](./样机灯光变化规律.md)），任何最终可见的颜色/模式变化都会反映在数据流内容里。

## 可能的功能（按可能性排序）

| # | 假设 | 市场常见做法 | 与"完全无效果"是否吻合 |
|---|------|-------------|---------------------|
| 1 | 双色配置：Color1 / Color2 定义动态动画（Fade 渐变、Strobe 闪烁、追跑）使用的两种颜色，需再按 Red / Green / Blue / White Select 分配；图标键即这类"双色组合"的节日快捷预设 | 双色/糖果拐杖式灯串（红白、橙紫、红蓝等两种颜色交替）上常见的"Color A / Color B"配置键 | 吻合：单独按只是进入"目标选择"状态，本身不改变输出 |
| 2 | 自定义颜色记忆：长按（约 2~3 秒）把当前颜色存入 Color1 / Color2，短按调出 | 24/44 键 RGB 遥控器上的 DIY1~DIY6（长按存、短按取）在消费级遥控器上的简化版 | 吻合：从未存过则短按无效或无可见变化 |
| 3 | 多 SKU 预留键：面板共用，本型号固件未映射这两个键（可能对应带白光版/双串版/更多颜色键版本的功能） | 通用遥控器面板 + 同 PCB 多型号出货是行业常态（12 个空键位是旁证） | 完全吻合：发了码但灯控数据流不变 |
| 4 | 动态模式的配色方案（Palette）切换：决定 Fade/Strobe 等动画用哪组颜色、是否混入白色 | 部分控制器的"Color Mode / Palette"键 | 半吻合：静态模式无效果合理；动态下若模式是单色渐变/单色闪，切换配色肉眼可能看不出差别 |
| 5 | 显示类型切换：多彩 / 暖白 / 混合（配合 White Select 选白光色温），面向"彩色+暖白双芯片"灯串型号 | 双芯片（multicolor + warm white）节日灯串的常见配置 | 半吻合：若本样机是纯彩色版则无效果，等同于预留 |

## 区分实验（可在样机上直接做）

1. 抓灯控数据流（最有决定性）：逻辑分析仪接样机 9 脚，分别在"按 Color1/Color2 前后"抓取逐灯数据帧做内容对比。
   - 帧内容完全不变 → 固件根本没处理该键，属于假设 3（预留键），功能可自行定义。
   - 帧内容变了但肉眼看不出 → 键是有效的，只是进入了内部状态（假设 1/2/4），继续做组合键实验。
2. 组合键实验（区分假设 1 与 2）：
   - 按 Color1 → 再按 Red / Green / Blue / White Select，看颜色是否变化或有闪烁确认反馈；
   - 在某个颜色下长按 Color1 / Color2（2~3 秒）看是否有保存反馈（闪烁/呼吸），然后切到别的颜色再短按，看是否恢复。
3. 记忆持久性验证（辅助判断假设 2）：若短按有恢复效果，先确认存的颜色是只在开关灯之间保留（RAM），还是断电后也保留（flash）。已知样机状态只在开关灯之间保留、断电即失。
4. 空口对比（辅助判断假设 3/4）：抓 2.4G 收包，对比 Color1/Color2 与其它键的码值。若与某键码值重复 → 丝印冗余；若有独立码值但灯控数据流无变化 → 预留键。

## 固件实现建议

- 在键值→功能映射表中把 Color1 / Color2 单独成项，暂按假设 1（双色配置）或假设 2（颜色记忆）实现，做成一行宏/枚举即可切换，等供应商键码定义确认后收敛。
- 不要在未确认前把它们并入 Modes 循环，避免和后续真实功能冲突。
